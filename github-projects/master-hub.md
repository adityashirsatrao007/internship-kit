## Naming convention

Repos keep **clean, generic, skill-signaling names** (e.g. `order-matching-engine`, not
`goldman-matching-engine`). This is intentional:

- Recruiters evaluate repos on their own merit; role names look like application spam.
- Several repos serve multiple roles (same repo, different resume framing) — one name, many uses.
- This page (the hub) is where the role ↔ repo mapping lives.

## How to use

1. Pick a company from the **quick lookup** table → it lists the resume + repos.
2. Compile the `.tex` resume (Overleaf → pdfLaTeX; `rirekisho-*.tex` → XeLaTeX).
3. Paste the repo links into the application / put them on your GitHub profile.
4. For a new company: add a row to the quick-lookup table pointing at the closest role.
